# 구독 DB 백업·복원

전용 DB만 매일 암호화해 기존 비공개 OCI 보관소의 newsletter/ prefix에 저장한다. 다른 DB·클러스터 백업은 변경하지 않는다. 암호화 수신 키는 기존 클러스터 복구용 공개 수신 키를 사용하고 개인 복호화키는 운영 서버에 배치하지 않는다.

7일 초과 객체는 새 백업 성공 여부와 무관하게 별도 시간별 작업에서 삭제한다. 따라서 정상 실행 시 만료 후 최대 약 1시간의 처리 지연이 있으며, 호스트·OCI 장애 중에는 삭제 시각을 보장할 수 없다. 개인정보 안내에서 정확히 168시간 내 물리 삭제를 보장하지 않는다. 실패한 작업은 systemd 상태·journal에서 확인한다. 외부 자동 알림은 아직 연결되지 않았다.

복원은 서비스 수집·내보내기를 중지하고 승인된 격리 DB에서 먼저 진행한다. 사용자 보관 개인키로 age 복호화 후 pg_restore --no-owner --no-acl을 전용 migration owner로 적용한다. 복호화 파일·CSV는 보호된 임시 위치에만 두고 검증 후 삭제한다. runtime 권한 SELECT/INSERT/DELETE와 schema 제한을 재검증한다. 이메일로 수신한 해지 요청을 복원 데이터에 먼저 재적용하고 완료 확인 후 서비스를 재개한다. 과거 CSV 재사용 금지. 기존 운영 DB를 무조건 덮어쓰지 않는다.

초기 백업에서 pg_restore --list 구조 확인과 암호화 업로드 후 다운로드 checksum 확인을 수행한다. 실제 복호화·격리 DB 복원 시험 완료를 뜻하지 않는다. 해지 요청 수신함 접근·대조 담당은 배포 담당자가 운영 전에 확인한다.
